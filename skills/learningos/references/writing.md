# Requested article drafting

## Ground the draft

Retrieve the learner's original notes and accessible source material. Identify the main argument, actual perspective and strongest supported insight. Ask a focused question only when a critical perspective is missing. Write in first person only where the notes support it.

Use simple conversational English, specific observations, natural sentence variation and genuine examples. Keep uncertainty and the learner's actual level of understanding. Do not invent dramatic stories, opinions, research findings or quotations; do not turn hypotheses into facts or pad length.

## Deliver the draft

Produce five title suggestions, three subtitle suggestions, a truthful introduction, logical sections, supported examples/reflections, a thoughtful conclusion and source acknowledgements when appropriate. Match length to real material.

Save versioned publication-ready Markdown outside the public skill repository: suggested title, subtitle, body, optional sources and optional diagram/image suggestions. Preserve notes and earlier drafts. If supported, set the external article status to Draft and read it back.

## Edit without inventing a voice

Load a prose-editing or humanizer skill only if available. Remove generic introductions, repeated transitions, rigid three-part structures, artificial enthusiasm, empty motivation, unnecessary adjectives and strained metaphors. Never add opinions or experiences the learner did not express. Do not promise AI-detector outcomes.

Learn voice only from writing samples the learner explicitly provides. Keep the sample-based style guide private; separate explicit preferences from inferred traits. Assistant-generated drafts are not evidence of the learner's voice. Show material edits and viewpoint changes rather than silently altering their perspective.

## Final checks and publication gate

Review accuracy, source grounding, original-note consistency, authentic perspective, readability, flow, attribution, unsupported claims and repetition. Explain material corrections.

Never publish without explicit approval of the final text and exact destination. If no verified publishing integration is available, provide copy-ready Markdown for manual publishing. After the learner confirms publication, record the supplied or verified URL, update a supported status to Published and read it back. Report manual publication as user-confirmed rather than independently verified when only the learner's confirmation is available.
